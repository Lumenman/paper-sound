# Звук на бумаге — руководство

Программа печатает аудио на лист бумаги в виде кривых и читает его обратно со
скана. Это не картинка звука и не QR-код: **лист и есть запись**, и прочитать
его можно линейкой, если хватит терпения.

Это руководство — для того, кто открыл папку впервые. Здесь: как оно устроено,
что настраивать, как печатать, как сканировать, как проверять результат и что
делать, когда вышло плохо. Формат и его измерения подробно описаны в
`README.ru.md` рядом, лабораторный журнал со всеми цифрами — в `LAB.ru.md`
там же.

Все команды ниже даны так, как их запускают **из корня проекта** (папкой выше):

```
python paper-sound/paper_sound.py ...
```

---

## 1. За пять минут

```
python paper-sound/paper_sound.py selftest                       # всё ли цело
python paper-sound/paper_sound.py print song.wav -o sheet        # -> sheet_01.png, ...
                                                                 # печатаем, сканируем
python paper-sound/paper_sound.py read sheet_01.png -o back.wav  # обратно в звук
python paper-sound/bench.py sheet_01.png song.wav                # насколько похоже
```

`selftest` печатает лист в памяти, читает его обратно и проверяет два десятка
вещей. Если он зелёный — установка в порядке:

```
selftest ok: 10 lanes at 600 Hz, round trip 0.9998, clock 0.800 -> 0.988, ...
```

**Что нужно:** Python 3, `numpy`, `Pillow`. Больше ничего: печать и чтение
обходятся этими двумя.

Необязательное: `scipy` — только для `picky.py` (чужой ридер полос); `sox` —
только для подготовки звука перед печатью, и любой годится, хоть из PATH, хоть
свой (§3).

## 2. Как это работает

### Один лан — секунда, одна строка — отсчёт

Лист разделён на вертикальные **ланы** (полосы). Один лан несёт одну секунду
звука. Внутри лана бежит штрих, и **на каждую строку пикселей приходится один
отсчёт**. Значит:

- высота печатной области в пикселях **и есть частота дискретизации**;
- ширина листа — это сколько секунд влезло.

A4 при 600 dpi с полями 5 мм: печатная область 4724 x 6780 px, шаг лана
38.7 px → **122 лана = 120 секунд звука на частоте 6780 Гц** (два лана уходят
под часы).

### Амплитуда — это положение, а не плотность

Отсчёт — это **положение штриха поперёк лана**, измеренное как центроид
чернил. Не количество чернил, не толщина, не серость. Из-за этого плотность
печати, экспозиция и гамма сканера выпадают из ответа: центроид меряется
относительно собственного центра лана и слеп к тому, сколько чернил легло.

Отсюда же главное правило сканирования: **всё, что двигает уровни, ломает
носитель**. Белая точка стоит 8.6 dB, молча и необратимо (см. §5).

### Часы

Крайние два лана — не звук, а **часы**: чистый тон, напечатанный как обычная
секунда. Они несут то, чего лист иначе сказать не может:

- **время.** Сканер не продвигается ровно на строку за строку; каретка рябит, и
  эта рябь общая для всех ланов. Часы её меряют и вычитают — на здешних листах
  это от +1.4 до +4.9 dB;
- **скорость.** Сколько строк пришлось на отсчёт (ключ `--rows`, §4);
- **какой стороной лист лежал на стекле.** Двое часов напечатаны с разными
  периодами (32 и 20 отсчётов на цикл), и если они прочитались в обратном
  порядке — лист лежал вверх ногами, и чтение поворачивается само.

### Что лист говорит о себе сам

В файле нет заголовка, контрольной суммы и метаданных. Всё меряется со скана
при каждом чтении:

| что | откуда |
|---|---|
| шаг лана | периодика страницы (решётка), плюс медиана по третям — уход шага у каждой пары принтер+сканер свой |
| где резать ланы | самый чистый профиль колонок |
| частота дискретизации | высота чернил в строках |
| перекос и снос | собственный край чернильного блока, потом подгонка по полосам строк |
| строк на отсчёт, ориентация, рябь | часы |
| экспозиция, плотность | никак — центроид к ним слеп |

Поэтому другой сканер меняет числа, которые лист сообщает, а не код, который их
читает.

### Пределы формата

- **A4 при 600 dpi ≈ 6.8 кГц и 2 минуты на лист.** Это оптическая звуковая
  дорожка, а не CD. Длиннее — несколько листов подряд.
- **Нет ECC и нет заголовка.** Дырка в сетке — секунда тишины на своём месте.
- **Полный размах закрывает зазоры между ланами**, поэтому материал,
  нормированный «в полку», читается хуже (см. §3).
- **Перекос** терпится до тех пор, пока лист влезает на стекло (около 1.2° для
  A4 на A4-стекле), а не до какой-то настройки ридера.

## 3. Подготовка звука

Требования простые: **моно, 16 бит PCM**. Частоту лучше привести заранее к той,
которую держит лист (A4/600 → 6780 Гц): тогда ридер увидит `rate == sr` и не
станет ресемплить сам. Программа скажет, если это не сделано:

```
NOTE: song.wav is 44100 Hz and this sheet holds 6780; resampled here through
a 209-tap sinc. `sox in.wav -r 6780 out.wav rate -v 6780` is the same job
```

Готовые цепочки для речи лежат рядом: `prep.bat`, `prep2.bat`, `prep3.bat`.
Они делают полосу, компандер, лёгкий клип и ресемпл и печатают `sox --stats` в
конце. Внутри — измеренное меню плотности с ориентирами RMS и crest-фактора.

**Про sox.** Он нужен только здесь, для подготовки звука; ни печать, ни чтение
его не спрашивают. Bat-файлы сначала смотрят на свою копию в `..\sox\` (так
лежит в этом проекте), а если её нет — берут `sox` из PATH. Хватит любого:
поставить системно, положить куда угодно и добавить в PATH, или просто набрать
те же команды руками — ничего специфического в них нет.

Минимум, если возиться с компандером не хочется, — привести формат:

```
sox in.wav -b 16 -c 1 out.wav rate -v 6780
```

**Про громкость.** Печать нормирует лист сама — по 99.9-му перцентилю, а не по
пику. Значит, одиночный щелчок в исходнике больше **не** съедает размах: раньше
он забирал весь бюджет, и лист выходил тихим (померено: −2.1 dB на бумаге).
Крутить финальный `gain` бесполезно, программа всё равно перенормирует. А вот
средний уровень над шумом бумаги — по-прежнему дело компандера: носитель даёт
около 20 dB отношения сигнал/шум, а речь приходит с 22 dB crest-фактора.

Если аудио сжато так, что 99.9-й перцентиль почти равен пику, печать скажет:

```
NOTE: 0.42% of the samples print at the edge of their lane and are flattened
```

## 4. Печать

```
python paper-sound/paper_sound.py print song.wav -o sheet
python paper-sound/paper_sound.py print song.wav --paper letter --margin-mm 12
python paper-sound/paper_sound.py print song.wav --rows 2
```

| ключ | по умолчанию | что делает |
|---|---|---|
| `--paper` | `a4` | размер листа; можно `letter`, `a3` или `ШхВ` в мм |
| `--dpi` | `600` | разрешение печати; PNG несёт его в себе |
| `--margin-mm` | `5` | поля, которые принтер не достаёт |
| `--pitch` | `38.7` | шаг лана в px. Шире — чище, но меньше секунд на лист |
| `--rows` | `1` | строк на отсчёт; `2` даёт +1.9 dB ценой половины времени |
| `--start` | `0` | сколько секунд пропустить перед первым листом |

Печать сообщает, что получилось:

```
song.wav: 120 s at 6780 Hz, 122 lanes -> 1 sheet
  a4 210x297 mm = 4961x7016 px at 600 dpi, margin 5 mm, pitch 38.7 px = 1.64 mm
  sheet.png: 122 lanes, seconds 0-120, ink 4724x6780 px = 200x287 mm
```

**Печатать на 100%, в натуральную величину, без «вписать в страницу».** PNG
несёт свой dpi, и вменяемый диалог печати сделает всё сам. Если лист вышел
бледным — печатать заново темнее, **а не исправлять потом**: то, что не легло
на бумагу, ридер восстановить не сможет.

**Про `--dpi`.** Толщина штриха, зазор и апертура заданы в пикселях и за dpi не
следуют: при 1200 dpi штрих станет 0.085 мм, и струйник положит его дырками.
Печать это знает и говорит, называя нужные числа:

```
NOTE: 0.085 mm of stroke, against the 0.17 mm this format has been printed and
scanned at. STROKE 8 and --pitch 77 would keep the sheet the size it is at 600 dpi
```

**Про `--rows 2`.** Каждый отсчёт рисуется двумя строками: наклон чернил на
строку вдвое меньше, лист держит вдвое меньше звука, чтение выходит на 1.9 dB
чище. Кодировать ничего не надо — часы несут это число сами, и `read` флага не
требует. Дробные значения (1.5) невозможны, см. §12.

## 5. Сканирование

**Серый, тот же dpi, все правки выключены.** Без автоконтраста, без уровней,
без белой и чёрной точки, без резкости, без выравнивания, **не битонально**.
8 или 16 бит — одинаково.

Почему так строго: носитель — это доли пикселя на краю штриха, где чернила
покрывают пиксель частично. Белая точка обнуляет всё бледнее нескольких единиц
из 255 и стирает ровно эти пиксели: **−8.6 dB, молча и необратимо**. Ридер
умеет заметить следы правки по «расчёске» пустых корзин гистограммы и скажет:

```
sheet.png: levels have been adjusted after scanning (37 empty bins ...)
```

Но заметить — не значит починить. Единственный ответ — пересканировать.

Класть лист по направляющей. Перекос теперь дёшев (сетка режется по
собственному наклону листа), но лист всё равно должен целиком влезть на стекло.

**Три скана вместо одного.** Два скана одного и того же листа, теми же
настройками, с интервалом в минуты, разошлись здесь на **1.95 dB**. Всё, что
меньше этого, — разговор о сканере, а не о формате. Поэтому, когда меряете
что-то всерьёз, снимайте лист трижды, поднимая и опуская его между сканами, и
сравнивайте медианы (`bench.py --same`, §8).

## 6. Чтение

```
python paper-sound/paper_sound.py read sheet.png -o back.wav
python paper-sound/paper_sound.py read sheet_01.png sheet_02.png -o back.wav
```

Листы перечисляются **в порядке воспроизведения**; второй лист, отсканированный
в другом масштабе, приводится к частоте первого.

| ключ | когда нужен |
|---|---|
| `--aperture` | главная ручка чтения: ширина окна центроида в px. Крутить первой, если r низкий (§9) |
| `--pitch` | если сегментация промахнулась мимо шага |
| `--rows` | если часы повреждены: больше на листе этого числа нет |
| `--upside-down` | если лист напечатан до того, как часы стали разными, и играет задом наперёд |
| `--sr` | задать число отсчётов на лан вручную |
| `--no-pilot` | читать без часов (и без ретайминга) |
| `--despeckle` | подавление выбросов; **по умолчанию выключено**, и это измерение, а не осторожность: на чистом листе оно только портит (0.781 → 0.122 при пороге 2). Включать только для реально грязного листа |

## 7. Что печатает чтение

Ридер разговаривает языком дефекта. Ни одно из этих сообщений не прерывает
работу — чтение продолжается, но каждое что-то значит.

| сообщение | что случилось | что делать |
|---|---|---|
| `levels have been adjusted after scanning` | скан пропущен через кривую или уровни | пересканировать без правок |
| `NOTE: scanned upside down; the read was turned` | лист лежал вверх ногами, часы это увидели | ничего, уже исправлено |
| `both clocks are the 32-sample one` | старый лист: часы одинаковые, ориентацию сказать нечем | если играет задом наперёд — `--upside-down` |
| `only one clock` | второй лан повреждён или сетка переехала поле | ориентация не подтверждена, проверить на слух |
| `clocks on lanes 4 and 57 of 62 -- the lane grid overran the field` | сегментация захватила край стекла | лишние секунды пустые; кропнуть скан по бумаге |
| `no clock lanes found` | печатали без часов или сетка сильно промахнулась | ретайминга не будет; `--rows`, если лист был на 2 |
| `2 clock lanes found, carriage ripple 1.47 samples rms` | норма: на рендере 0.08, на бумаге около 1.5 | ничего |
| `lane 3 of 40 is 8 px against a median of 38` | что-то на листе сегментировано как полоса | **важно**: всё после неё сдвинуто на секунду |
| `the drift fitted down this page says ... the ink's own edges say ...` | подгонка сноса ушла с листа, перекос прочитан низко | пересканировать ровнее |
| `seconds 12, 13 of 120: no lane on the sheet to read there` | дырки в сетке | на их месте тишина, хвост не съезжает |
| `stretched to the first sheet's 6606 Hz` | второй лист снят в другом масштабе | ничего, приведён к первому |
| `pHYs carries a CRC its writer computed wrong; mended in memory` | сканер соврал в контрольной сумме служебного блока | ничего, файл на диске не тронут |

## 8. Проверка: как измерять сканы и звук

### `bench.py` — главный прибор

```
python paper-sound/bench.py sheet.png song.wav
python paper-sound/bench.py sheet_01.png sheet_02.png song.wav
python paper-sound/bench.py --same scanA.png scanB.png scanC.png song.wav
```

Последний аргумент — тот wav, который печатали; всё до него — сканы в порядке
воспроизведения. Печатает одну строку:

```
sheet.png   r=0.9383  lanes 57 at 6574 Hz  2 clocks  median 0.9354
            below 0.5: 1/56  worst 0.28 0.79 0.82
            below 0.5 at second 31
```

- **r** — корреляция всего чтения с оригиналом. В децибелах:
  dB = 10·log10(r² / (1 − r²));
- **median** — медиана посекундных r. Смотреть надо на неё и на распределение:
  ридер, потерявший две секунды из ста, почти не двигает общее r и очень
  слышен;
- **below 0.5** — сколько секунд провалено. **Где** они — это диагноз:
  разбросаны поодиночке = дефект отдельных ланов (смотреть полосы, §11); одной
  длинной пачкой = бумага (складка, полоса ряби, край стекла);
- **worst** — три худшие секунды. Для речи это часто просто паузы, а не сбои.

**Чего ждать.** Лист прямо из `print`, не видевший бумаги: **r > 0.999** —
меньше означает, что сломан ридер, а не бумага. Напечатанный и отсканированный:
**0.92…0.98**, и разница между листами — это сканер, а не формат. **Ниже 0.85
что-то стоит искать**, и предупреждения из §7 — с чего начинать.

**`--same`** говорит, что это один лист, снятый несколько раз, и добавляет
медиану и разброс. Пользуйтесь им, прежде чем поверить, что какая-то правка
что-то улучшила: разброс между сканами одного листа здесь доходил до 1.95 dB.

### Остальные приборы

| команда | отвечает на вопрос |
|---|---|
| `python paper-sound/score.py back.wav:song.wav` | то же, что bench, но для двух готовых wav (лист уже прочитан) |
| `python paper-sound/align.py back.wav:song.wav` | **где** чтение поехало: посекундный r вместе с посекундным лагом. Растущий лаг = уход масштаба, скачок = потерянный лан |
| `python paper-sound/spec.py back.wav:song.wav:метка` | **что лишнего** появилось в спектре: писк сканера, растр принтера (§10) |
| `python paper-sound/slope.py back.wav:song.wav:38.7` | теряет ли лист **на крутизне**: ошибка против наклона, который чернилам пришлось нарисовать. Потери только в верхних корзинах = виновата крутизна, ровные по всем = бумага |
| `python paper-sound/cmp_picky.py 6608 song.wav "reader" back.wav "picky" other.wav` | сравнить два разных чтения одного листа на одной метрике |

### Селфтесты

```
python paper-sound/paper_sound.py selftest      # формат: печать -> файл -> чтение
python paper-sound/cut_lanes.py --selftest      # нарезка полос
```

Оба проверяют реальные аварии, а не счастливый путь: перевёрнутый лист, убитые
часы, симметричный лист, битую CRC, дырку в сетке, лист с перекосом в 300 px,
16-битный скан. Запускать после любой правки.

## 9. Новая связка принтер + сканер

Настраивать, вообще говоря, **не нужно**: в коде нет ни одного числа, снятого с
конкретного железа, а всё, что от железа зависит, лист сообщает о себе сам
(§2). Но есть три места, где связка всё-таки видна.

1. **`--aperture`** — единственная ручка чтения, которая реально зависит от
   размытия цепочки. База (8 px при шаге 38.7) снята здесь и масштабируется
   шагом самого листа; более мыльный сканер захочет окно шире. Если r ниже
   ожидаемого, а предупреждений нет — свипуйте её первой.
2. **Геометрия штриха при печати** — 0.17 мм при 600 dpi. Другое dpi или грубый
   растр принтера меняют дело; печать выдаёт NOTE и называет числа (§4).
3. **Обратный фильтр (необязательно).** Цепочка печать+скан работает как мягкий
   ФНЧ, и часть её потери можно снять фиксированным фильтром. Померено: на трёх
   разных листах одной связки ошибка повторяется на ρ ≈ 0.33…0.56, а компенсация
   дала бы +0.8…+2.1 dB. В программе этого нет: такой фильтр стал бы первым, что
   привязано к конкретному железу, и жить он должен файлом калибровки, а не
   константой.

**Чеклист на первый лист новой связки:**

1. напечатать 600 dpi, 100%, в натуральную величину;
2. отсканировать серым на 600 dpi со **всеми правками выключенными**;
3. `read` — прочитать предупреждения (§7); они и есть диагностика связки;
4. `bench.py` — сравнить с ориентирами §8;
5. если низко — сначала `--aperture`, потом всё остальное;
6. прежде чем что-то чинить — три скана и `--same`.

## 10. Писк сканера: найти и подавить

**Откуда.** Одна строка листа = один отсчёт, поэтому **любая периодика строк
сканера садится прямо в звук как тон**. Чистая белая бумага на здешнем сканере
даёт полосы с одинаковым периодом на всех листах — значит это стекло, а не
формат.

**Найти:**

```
python paper-sound/spec.py back.wav:song.wav:метка
```

Печатает, где в чтении есть энергия, которой не было в оригинале. Настоящий
вывод на здешнем листе D:

```
sheetD_scan1 (6606 Hz)
        67.7 Hz   +23.6 dB over the source   (a feature every  97.52 rows)
       108.1 Hz    +2.6 dB over the source   (a feature every  61.13 rows)
      1646.7 Hz   +18.3 dB over the source   (a feature every   4.01 rows)
```

«a feature every N rows» — это период узора в строках листа. Читать так:

- **низкий широкий пик** (67.7 Гц, ~98 строк) — это медленный снос страницы и
  собственный низ записи, а не писк; нотчем его не лечат;
- **узкий пик наверху** (1646.7 Гц, ровно 4.01 строки) — вот это стекло.
  Целое число строк на период — верный признак: узор привязан к строкам
  сканера, а не к звуку. На листе, напечатанном с `--rows 2`, частота вдвое
  выше, чем на обычном (здесь 1647 против 823 Гц: те же 8 строк бумаги).

На другом сканере частота будет другая; ищите самый высокий **узкий** пик,
период которого близок к целому числу строк.

**Подавить** — узким режекторным фильтром, снаружи, при прослушивании:

```
sox back.wav clean.wav equalizer 823.4 40q -30
sox back.wav clean.wav equalizer 1647  40q -30    # лист, поднятый вдвое
```

Высокая добротность (`40q`) обязательна: писк — чистый тон, и речь вокруг него
нужна целой.

**Почему этого нет в самом ридере.** Частота — свойство конкретного стекла, а
не формата, и фиксированный нотч в `read` поставить нельзя. Вычитание общего
построчного узора пробовалось и обошлось дороже самого тона. Это вопрос
комфорта на прослушивании, а не починка чтения: **корреляция от нотча почти не
двигается, слышно становится заметно лучше**. Проверить, что нотч не съел
полезное, можно тем же `score.py` до и после.

## 11. Полосы и чужие ридеры

`cut_lanes.py` режет скан на отдельные картинки-полосы, по одной на лан:

```
python paper-sound/cut_lanes.py sheet.png -o strips
```

Полоса — **картинка строк**: маска вокруг собственного штриха, негатив (чернила
светлые), растянутая к общей высоте. Это материал для стороннего ридера (в
комплекте `picky.py` — порт Picture Kymophone Патрика Фистера) и инструмент
диагностики: если `bench` показал разбросанные плохие секунды, смотреть надо
именно на эти полосы.

Нарезка печатает под собой самое важное:

```
  one strip is 6608 rows and holds 1/2 of a second, so the audio on it is
  6608 Hz -- and a reader that takes one row for one sample has to play it
  at 13216 Hz
```

**Две разные частоты, и путать их нельзя.** Звук на полосе — 6608 Гц. Но
`picky` и всё подобное берут **строку за отсчёт** и ничего не знают про
`--rows 2`, поэтому им надо называть **частоту строк** (13216), иначе запись
выйдет вдвое длиннее и вдвое ниже.

Рабочая команда для полос:

```
python paper-sound/picky.py x 50 3 d 165 1 0.95 pdp 13216 24 "strips/*.tif"
```

Здесь важны два аргумента: `165` вместо `330` (без 20-герцового ФВЧ на каждую
полосу — он стоит 0.93 → 0.73) и частота строк вместо частоты звука.

**Потолок этого пути** — 0.88…0.93 против 0.98 у `paper_sound`, и это не
поломка: в полосах нет часов (то есть нет ретайминга), нет приведения ланов к
общей длине в отсчётах и нет узкого окна центроида. За звуком с листа идти надо
в `paper_sound`.

## 12. Частые вопросы

**Можно ли `--rows 1.5`?** Нет. Печать бы это нарисовала, но лист сообщает
`rows` периодом часов, а ридер сажает измеренное на лестницу из четырёх
ступеней (20, 32, 40, 64 строки). Дробное значение либо падает между ступенями
(часы пропадают), либо совпадает с чужой: 20 × 1.6 = 32, то есть лист «на 1.6»
неотличим от обычного, и ориентация теряется молча.

**Можно ли напечатать «карту ошибок» вторым набором кривых, чтобы читать
точнее?** Померено: ошибка повторяется между сканами одного листа на ρ ≈ 0.6, и
идеальная карта дала бы +1.4 dB медианы за половину листа. Ровно ту же половину
листа стоит `--rows 2`, который даёт +1.9 dB и не требует ни второго прохода,
ни привязки к сканеру.

**Почему чтение звучит тише или громче оригинала?** Оно нормируется по 99.9-му
перцентилю, а не по пику: иначе один потерянный лан, машущий во всю ширину,
задавил бы весь файл на 11 dB.

**Лист играет задом наперёд.** Часы одинаковые (старый лист) — читать с
`--upside-down`.

**Второй лист звучит на другой высоте.** Он отсканирован в другом масштабе;
читайте оба листа одной командой, тогда второй приводится к первому.

## 13. Симптом → причина

| симптом | причина | что делать |
|---|---|---|
| r ниже 0.85, предупреждений нет | окно центроида не под размытие связки | свип `--aperture` |
| r около нуля, звук неузнаваем | лист сегментирован не по тому шагу | `--pitch` вручную; посмотреть, не попал ли в скан край стекла |
| всё после какой-то секунды сдвинуто | лишняя «полоса» в сетке | предупреждение `lane N of M`; кропнуть скан по бумаге |
| глухой звук и шелест | подкрученные уровни или белая точка при сканировании | пересканировать без правок |
| тонкий чистый тон поверх записи | периодика стекла | `spec.py`, потом `sox equalizer` (§10) |
| щелчок раз в секунду | стык ланов; при чтении одной командой сглаживается сам | читать все листы одним вызовом |
| запись вдвое длиннее и ниже | полосы играются строка-в-отсчёт без учёта `--rows 2` | назвать частоту строк (§11) |
| бледные, рваные штрихи на бумаге | принтер: слишком тонкий штрих или мало чернил | печатать темнее; крупнее `--pitch` / `--dpi` по числам из NOTE |
| «the fit has left the sheet ... Rescan it straighter» | подгонка сноса ушла с листа | положить лист ровнее и переснять |
